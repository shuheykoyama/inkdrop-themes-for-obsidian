**Obsidian 側の制約（テーマで制御できる範囲）**

- 行番号の表示そのものは、Obsidian のネイティブ設定（設定 → エディタ → 行番号を表示。Vault の設定値 `showLineNumber`）で利用者が有効にする。**テーマ CSS は行番号を表示させることも、この設定を変えることもできない。** テーマが担うのは、行番号が表示されたときのガターの文字色・背景・境界線と、アクティブ行のガターの背景である。
- アクティブ行のハイライトはテーマ CSS だけで表現できる（Obsidian にはアクティブ行の既定のスタイルも設定もない。V-01 #8）。
- Style Settings などの独自の切り替えは設けない（Q-D17）。
- 作業でユーザーの Obsidian の設定を変更しない。検証は隔離した Obsidian とテスト Vault で行う。

**実装時に追加で検証が必要な事項**（[14](14-implementation-plan.md) の工程 7 と V-34・V-35）

1. Source mode と Live Preview のそれぞれで、`.cm-line.cm-active` と `.cm-gutterElement.cm-active` が付く条件（フォーカスの有無、複数カーソル、選択範囲がある行、折り返された行）。
2. アクティブ行の背景とアクティブ行のガターの背景が視覚的に連続すること（ガターと本文の境界の画素）。
3. KD のガターの右境界線を描く方法: app.css の `border-right: none !important` を `!important` 付きの `border-right` で上書きする（Inkdrop と同じ 1px の幅を持つ）か、`box-shadow` で描く（幅を持たない。V-07 で実証済み）か。前者は実機で未確認。
4. 選択範囲・検索ハイライト・対応括弧・選択一致・コードブロックの行・Live Preview のウィジェット（表、埋め込み）との重なり。
5. 行番号を無効にした場合（利用者の既定）に、アクティブ行のハイライトだけが正しく出て、ガター関連の規則が副作用を起こさないこと。
6. translucent 時（acrylic のエディタ面の上）のアクティブ行の見え方。Inkdrop の acrylic 用の規則はアクティブ行を変えない（STATIC、02 §1.4 の条件付き上書きに含まれない）が、合成結果は未確認。
7. 長い行を折り返さない設定で横スクロールしたときのガターの背景。Inkdrop は `.cm-gutters-hscrolled` で不透明の色（`--editor-gutter-background-solid-color`）に切り替えるが、Obsidian に同じクラスはない。
8. モバイル（エミュレーションと実機）での行番号とアクティブ行。
