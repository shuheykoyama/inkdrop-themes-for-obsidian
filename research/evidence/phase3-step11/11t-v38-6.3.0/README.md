# V-38（Inkdrop 6.3.0 と Obsidian 1.14.5 / Electron 43.8.3）の本測定（2026-11-03）

[14](../../../14-implementation-plan.md) §6.184 の証拠。ユーザーの「V-38 の実測を始めてよい。準備できた」のあと、既存の道具（`tests/visual/capture-inkdrop.sh`・`capture-obsidian.sh`・`sample-regions.py`・`v38-compare.py`、`tests/runtime/inkdrop-production.sh`）だけで行った。7 組、撮影の領域、平らさ ≤ 1.0、ΔE2000 ≤ 1.0 は変えていない。**結果は「Inkdrop 6.3.0 に対する実測」で、Inkdrop 6.2.0 に対する V-38 は UNVERIFIED のまま。6.2.0 の `verifiedBy` には転用しない。**

## 条件

- **Inkdrop**: 6.3.0（`CFBundleShortVersionString` とデバッグ接続の User-Agent `inkdrop/6.3.0`）。デバッグ接続（127.0.0.1:9334）で起動。窓は 1 つだけ（6.3.0 の窓の復元で、複数の窓や別のノートは出なかった）。テーマは SD 2.2.1・KD 1.2.1（インストール済み。撮影ごとに `core.theme` を切り替える）。サンプルノート「Basic writing and formatting syntax」。更新の通知なし。撮影の前後で、ノートの ID・リビジョン・`updatedAt`・題名が同じ。
- **Obsidian**: 1.14.5、Electron 43.8.3（隔離インスタンス）、translucent、最終の製品 CSS（SD `f6b59e61…`、KD `9cc55c6f…`）。**撮影専用の隔離 Vault は、`52434a5` の fixture（4 ノート）の複製**（5 ファイルの SHA-256 が `fixture-52434a5.sha256`〔`11s-v38-6.3.0-trial/`〕と一致。撮影のあとも同じ: `vault-notes-sha256-at-end.txt`）。現行の `tests/fixtures/vault` と通常の Vault は変えていない。エディタには `Other note` を表示（`CAPTURE_NOTE`）。
- **撮影**: 窓 1200×700 を (400, 250)、背景 1400×900 を (300, 150)、`screencapture -x -R400,250,1200,700`。ディスプレイは外付けの LG（1920×1080、倍率 1、プロファイル `LG FULL HD Calibrated`）。画像は 1200×700 px。**2026-10-11 の V-38（内蔵 Retina、倍率 2、`Color LCD`、2400×1400 px）とは条件が違うので、直接比べない**（`../11s-v38-6.3.0-trial/display-conditions-6.3.0.txt`）。
- **測定設定**: **元の `tests/visual/configs/v38-obsidian.json` と `v38-inkdrop.json`**。試しの撮影（SD・灰色・アクティブ、`trial/`）で、7 組すべてが有効（Obsidian のエディタの矩形 (850, 260, 80, 390) も、左ドックの矩形 (60, 200, 220, 420) も平ら）だったので、事前に承認されたフォールバック（`v38-obsidian-6.3.0.json`）は使わず、元の設定に確定した（`config-fixed.txt`）。本測定の途中で設定を切り替えていない。SD・KD で同じ設定。
- 撮影した時刻（UTC）: 試しと本測定 12:34〜12:41。本測定の 12 枚は、各テーマで Inkdrop と Obsidian を交互に、組の間隔は約 12 秒。

### 柄の背景・アクティブ（記録のみ）

14 組のすべてが、少なくとも一方の領域で標準偏差が 1.0 を超え、測定無効（`compare-pattern-active.csv`）。判定には使わない。**ただし、どちらも縞が透けているわけではない**（独立レビューの指摘、2026-11-03）: サイドバー ↔ Ribbon では、Inkdrop のサイドバーの標準偏差が SD 9.71・KD 9.62（背景の縞が透けて画素が変動する）のに対し、Obsidian の Ribbon は 0.00（変動がない。平均色も違う: SD `(34, 43, 48)` 対 `(22, 43, 48)`、KD `(41, 29, 27)` 対 `(29, 29, 27)`）。ノートリスト系は両側で変動がある（標準偏差 約 5〜6）。つまり、Ribbon と Inkdrop のサイドバーの**透過の挙動に差がある**（平坦性による測定無効とは別の問題。完成度のレビューで検討する）。

## 画像の目視確認

本測定の 12 枚と試しの 2 枚を、すべて全体画像で見た。対象のアプリの窓だけが写っていて、ほかの窓・通知・個人の内容はない（Inkdrop はチュートリアルのノートと公開のサイドバー、Obsidian は撮影専用の Vault）。非アクティブの 4 枚は、窓のボタンが灰色（アクティブでない）。柄の 4 枚は、縞が窓の背後から透けている。Inkdrop の `is-blurred` の記録も、アクティブ（false）・非アクティブ（true）で一致。

## 復元

- Inkdrop: 通常の終了 → `config.json` を控えで戻し → 通常の起動（`RESTORED`、9334 閉）。強制終了なし。サンプルノートの ID・リビジョン・`updatedAt`・題名は、撮影の前後で同じ（`note-before` と `note-after` を比較。ID は記録に入れていない）。`state-cache` は 8 件で前後同じ。データベースと同期の状態は、設計上、復元・比較の対象外。
- Obsidian: 隔離インスタンスを停止、ポート 9333 は閉。撮影専用 Vault のノートは前後で同じ。LaunchServices は `restore` のあと、`check` が作業の前と同じ出力（`ls-before.txt`・`ls-after.txt`）。

## 確かめていないこと

- **Inkdrop 6.2.0 に対する V-38**（実行環境がない。UNVERIFIED）。この結果を 6.2.0 に当てはめてよいかは、静的な CSS の差（§6.180）と対象の領域の構造から別に整理する。静的な差がなくても、描画が完全に一致するとは断定しない。
- 内蔵 Retina（倍率 2）の条件での撮影、2026-10-11 の結果との直接の比較。
- 非アクティブでの Obsidian と Inkdrop の差（記録のみ。判定の対象外）。
