### 灰色の背景・非アクティブ（記録のみ）

Inkdrop は非アクティブでも値が変わらない（アクティブと同じ）。Obsidian は Ribbon とノートリスト系の面が暗くなり、ΔE2000 は Ribbon 2.19（SD）/ 2.25（KD）、ノートリスト系 1.23 / 1.26、エディタ 0.31 / 0.31。Inkdrop はウィンドウを `visualEffectState: 'active'` で作り（11 §15.5、STATIC）、Obsidian は指定しない（Electron 既定の `followWindow`、12 §3.1、STATIC）ため、非アクティブ時の素材が違う。ウィンドウの設定はテーマの CSS では変えられない。

### 柄の背景・アクティブ（記録のみ）

両アプリとも背景の縞が透け、すべての領域で標準偏差が 1.0 を超えた（測定無効）。V-32（2026-10-10）では Inkdrop に縞は透けていなかった。

## 工程 4 の差の原因（事実と推論の区別）

| 区分 | 内容 |
|---|---|
| 事実（実測） | 工程 4 の Obsidian の撮影（2026-10-11 11:12Z ごろ）は V-32 の Inkdrop（2026-10-10 03:16Z）と最大 ΔE2000 3.2 違った |
| 事実（実測） | 同じ日（11:15Z）に撮り直した V-04 の診断用 CSS は、同じ acrylic のトークンの面でテーマと同じ画素だった（`phase3-step4/`） |
| 事実（実測） | 同じ時刻の Inkdrop（本書）は、Obsidian と同じ画素だった。Inkdrop 自身の値も V-32 から同じだけ変わっていた（例: SD のサイドバー (22.5, 43.8, 48.5) → (32, 53, 58)） |
| 事実（設定の読み取り） | 壁紙は macOS 標準の HEIC 画像、「ウインドウで壁紙の色合いを調整」はオン、外観はダーク、透明度を下げるはオフ |
| 推論（未実証） | 両アプリのウィンドウ素材の下地が、撮影時刻（日中と夜）の違いで変わった。時刻で変わる壁紙と、壁紙の色合いをウィンドウに反映する設定が原因と考えられる。確かめるには、設定を変えるか、同じ日の別の時刻に撮り直す必要がある（行っていない） |

したがって、テーマ（CSS）の値の問題ではなく、比較の基準画像が別の時刻のものだったことによる差である。同じ時刻の比較で閾値内に入ったため、現在の環境での視覚的忠実度は PASS とした。

## 実際の macOS のフルスクリーン（`measurements/obsidian-real-fullscreen.json`）

ユーザーの承認を得て、隔離した Obsidian（Electron 43.7.7、KD、translucent 有効）のウィンドウだけを実際にフルスクリーンにした。フルスクリーン中は `body` に `is-fullscreen` が付き、Ribbon (17, 17, 14)・ステータスバーとタブ帯と Vault 名の領域 (24, 22, 22)・エディタ (30, 29, 26) と、すべての面が不透明の Inkdrop の色（S7 の実測値と同じ）になった。解除すると acrylic の値に戻った。SD ではフルスクリーンにしていない（規則は共通で、値だけが違う）。

## 後片付け（確認済み）

- Inkdrop: テーマを Solarized Dark（作業前の設定）に戻し、通常終了したあと `config.json` を終了直後の控えで書き戻した。パッケージ一覧は作業前と同じ。サンプルノートの `updatedAt` は作業の前後で同じ。デバッグなしで通常起動し、9334 番ポートが閉じていることを確認した。
- Obsidian: 隔離インスタンスを停止し、9333 番ポートが閉じていることを確認した。現行インストーラのコピーの LaunchServices の登録を解除し、`obsidian://` の候補が `/Applications/Obsidian.app` だけに戻ったことを確認した。普段の Obsidian には触れていない。
